# 中文导读：这个 POS 要怎样做

## 1. 项目定位

你的目标不是再做一个 ERP，也不是复制整个 Odoo，而是把你熟悉的商品、销售和库存流程，做成小店店员容易操作的收银产品。暂名 **Counter POS**；这个名字、技术栈和 repo 名称都是本次建议，尚未成为你确认的项目决策。

第一版以一间店、一个库存地点、一个正在收银的设备为基准。后台可以另开浏览器管理商品，但不能假设多部断网设备同时卖最后一件商品仍然不会超卖。几样或几十样商品即可展示完整流程；测试数据另外覆盖 500 个商品，用来验证性能，不是宣称已经达到的性能成绩。

## 2. 第一版要交付什么

完整业务链是：建立商品 → 登记进货数量 → 登录并开班 → 点商品加入购物车 → 收款并保存销售 → 开收据 → 产生库存 movement → 查看销售 → 交班对账。

店员只需要看到商品、购物车、付款和清楚的状态。商品成本、调库存、退款批准和设置留在后台。桌面和平板采用商品区加右侧订单区；手机采用商品区加底部“查看订单”，再进入全屏订单和付款。不要把 ERP 那种很多字段的表单直接搬进收银界面。

## 3. Product 不等于 Inventory

**Product / 商品资料**回答“这是什么商品、卖多少钱”。**Inventory / 库存**回答“现在还有多少”。

商品表不应该成为随意更改库存的入口。收到 20 件写入 +20 的库存流水；卖出 2 件写入 -2；退回且可以再卖的 1 件写入 +1。库存余额是流水的可重建汇总，更新销售、付款和库存必须放在同一个服务器 transaction 中。历史售价和税额保存于销售明细，不受今天修改商品价格影响。

## 4. 离线不是无限制

离线功能是在之前已联网登录、下载商品、开班和获准离线操作之后，继续登记现金销售。第一次登录、修改价格、进货、库存调整、退款及正式关班要求联网。

离线销售会显示 **Saved on this device / 已存本机** 和待同步数量，不能假装已经同步到服务器。重开页面、恢复网络、回到应用和手动点击同步都要触发尝试。Background Sync 仅作额外优化，不作为所有浏览器都具备的前提。浏览器储存空间也可能不足或被用户清除，所以不能承诺本机资料永远不会丢失。[S03, S04]

离线付款只开放 Cash。Card 和 PayNow 在 V1 是店员已经在外部终端或商户渠道确认后手动登记的方式，不是系统自动验证到账。不能看到顾客截图就当作可靠的收款结果；真实支付集成应另立项目范围。

## 5. 防止重复收款和重复扣库存

点两次“完成销售”、网络 timeout 或同步重试，不应该生成两笔销售。每一笔本机销售有固定 UUID，后端保存这个 ID 和内容摘要。同样 ID、同样内容只返回原结果；同样 ID、不同内容必须报冲突。

**Idempotency / 幂等**：同一个请求重试多次，业务只记一次。它不是不需要测试的保证。测试必须真的模拟服务器保存成功但响应丢失，然后再重试，核对销售、付款和库存流水都只有一份。

## 6. 退款、作废和交班

购物车还没收款，可以取消草稿。已完成销售不可直接删除，应通过关联原单的退款记录反向处理。退款数量不能超过原购买数量，已退过的不能再退。是否回库存由商品实际可否再售决定。

交班不是只显示今日销售总额。预计现金 = 开班备用金 + 现金销售净额 - 本班现金退款 + 现金存入 - 现金取出。现金找零不是销售收入。待同步销售未处理完时，可以保存点钞草稿，但不能假装完成最终对账。

## 7. 这套 ZIP 怎样使用

先看 `START-HERE.html` 和 `UI-Design-Atlas.pdf`。你可以用 `prototype/index.html` 体验商品加入订单和模拟现金结账；它只用于讨论 interaction，刷新会清空，不是正式系统。

把整个目录交给 AI Agent，并让它先读 `prompts/IMPLEMENTATION-TASK.md`。Agent 必须先 audit 环境、建立隔离 branch/worktree、确认依赖和测试，然后逐阶段实现；不能看到 SQL 文件就直接对你的 ERP 数据库执行，也不能自行部署到现有生产服务。

## 8. 简历怎样展示

完成后最有价值的演示是：一笔正常现金销售、一笔断网后重连的销售、一次重复提交测试、一次退款及库存对照。README 展示真实运行证据、架构取舍和已知限制。现在只能说“设计规格与交互原型完成”，不能写“已经上线使用”或虚构测试通过率。

术语：**wireframe** = 线框图；**design tokens** = 统一颜色、字号与间距变量；**outbox** = 待同步队列；**stock movement** = 库存流水；**reconciliation** = 对账；**acceptance criteria** = 验收条件。
